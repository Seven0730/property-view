## 数据分析

数据覆盖 2026 年 9 月 1—7 日，原始 1,307 条，剔除 62 条完全重复记录后，有 1,245 次独立预约：
- 1,020 次正常带看，169 次跑空，56 次结果未回传。
- 已回传结果的跑空率为 169 ÷ 1,189 = 14.21%，约每 7 次带看跑空一次。
- 按每次损失 120 分钟，已确认损失合计 338 小时。
- 未回传不能当作成功；如果全部成功或全部失败，全量跑空率分别为 13.57%—18.07%。

## 问题定位

- 华东、华北、西南：状态更新不及时，或出发前确认不足。 状态较新时跑空率仅 2.5%—3.9%，超过 10 分钟后升至 48%—52%。这类预约贡献了全部已知跑空的 75.1%，是首要排查方向。
- 华南：临近租罄时的库存保障不足。 剩余 ≤3 套时跑空率 39.6%，>3 套时仅 1.5%；即使刚同步过，低库存组仍高风险。

## 优化计划

仅通过数据分析无法直接消除房源状态与实际可看情况之间的差异。

因此，建立出发前风险提醒与复核机制：优先核查高风险预约，确认具体房源是否可看；对确认不可看的预约提前更换房源或改约，在减少到场跑空的同时，避免误取消正常带看。


## 产出说明

`property_view.py` 是独立的 Python 脚本，有两个功能：

- `batch`：批量分析 CSV，输出每条预约是否提醒、原因，以及整体跑空率、提醒率、提醒组和无提醒组的跑空率。
- `single`：分析单条数据，输出是否提醒、原因和状态时延。

两个功能共用同一规则：华东、华北、西南状态时延 >10 分钟，或华南库存 ≤3 套时提醒；未支持的区域提醒人工核查。

### 批量分析

在仓根运行：

```sh
python3 property_view.py batch --input property_viewings.csv --output reports
```

### 单条分析

```sh
python3 property_view.py single --data '{"region_name":"华北大区","available_units":8,"viewing_time":"2026-09-05T10:00:00+08:00","status_synced_at":"2026-09-05T01:40:00Z"}'
```

## 优化结果

优化成果：通过风险提醒，将大部分历史跑空识别出来，让无提醒预约的风险明显降低。

| 指标 | 原整体（已回传） | 规则筛选后的无提醒组（已回传） |
|---|---:|---:|
| 预约数量 | 1,189 | 887 |
| 跑空次数 | 169 | 23 |
| 跑空率 | **14.21%** | **2.59%** |

规则将 313 次预约标记为需复核，占全量的 25.1%，其中包含 146 次已知跑空，覆盖全部已知跑空的 86.4%。

- 提醒率 = 提醒预约数 / 去重后全部预约数 = 313 / 1,245 = **25.14%**。
- 已知跑空覆盖率 = 提醒组跑空次数 / 全部已知跑空次数 = 146 / 169 = **86.39%**。
- 无效提醒率 = 提醒组正常带看次数 / 提醒组已回传次数 = 156 / 302 = **51.66%**。
